## Legenda de vereditos
- **CONFORME** — prova executada existe (roteiro ✓ no CI, teste Vitest verde, ou SELECT com resultado colado).
- **CONFORME-POR-LEITURA** — o código lê certo, mas sem prova executada (só leitura da migration/código vigente).
- **DIVERGENTE** — o sistema faz diferente da norma vigente (bug). Toda linha DIVERGENTE tem ação registrada.
- **DOC-DESATUALIZADA** — código certo por decisão registrada; a spec é que estava velha → emendada.
- **NAO-IMPLEMENTADO** — a norma promete e não existe em camada nenhuma.
- **SEM-PROVA** — regra sem cobertura executável → virou roteiro/teste nesta ordem, ou tem justificativa.

## Como reexecutar cada tipo de prova
- **Vitest (funções puras):** `npm run test` (roda em CI, job `verificar`).
- **Roteiros SQL (comportamento do banco):** job `banco` do CI (`.github/workflows/ci.yml`) sobe um Postgres, aplica `0001`→última migration e roda cada `supabase/tests/*.sql` com `ON_ERROR_STOP` (falha em `WARNING: ✗`). Localmente (sem Docker), provados no ENSAIO via MCP `execute_sql` em bloco `begin; … rollback;` que devolve LINHAS.
- **SELECTs de consistência de produção (Onda 3):** MCP `execute_sql` **read-only** no projeto de produção; comandos e contagens abaixo (§Onda 3).
- **Advisors:** `get_advisors(security|performance)` no MCP.

## § Emenda F49 (07/09/2026) — a fronteira do servidor

**Quatro regras novas, todas de FRONTEIRA — e as quatro rodam SEM BANCO.** A fase fechou as duas superfícies por onde o servidor é alcançado sem passar por tela: a **HTTP** (Server Action é endpoint) e a **RSC** (módulo de servidor arrastado para o bundle do cliente). Não houve migration (a última continua sendo a `0128`), nem alteração de policy, de RPC ou de grant: o banco não foi tocado, e por isso `npm run db:test` e `npm run db:test:mutations` continuam idênticos.

**A regra que faltava era a mais barata de escrever e a mais cara de não ter.** As policies de SELECT das tabelas de inventário seguem `papel_atual() is not null` (R-ACC-32) — o **piso de leitura**, que todo logado ativo atende. Isso é por desenho, e não muda aqui. Mas nove Server Actions de leitura **não chamavam guarda nenhuma**: quem tivesse um token válido e o perfil DESATIVADO — expulso de toda a UI por `getOperador()`, e ainda assim aceito pelo PostgREST até o token expirar — enumerava o acervo por POST direto.
